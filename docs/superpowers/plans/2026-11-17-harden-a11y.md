# Harden (accessibility resilience) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the small accessibility and robustness gaps found in the 2026-11-17 re-audit without changing how the app looks for people who haven't asked for reduced motion.

**Architecture:** One reduced-motion block in `app.css` plus tidy-ups in the few places that animate; focus, button, table and login fixes in the pages that have them. No new dependency, no data or API change.

**Tech Stack:** SvelteKit 2 / Svelte 5 CSS and markup.

**Spec:** Re-audit findings, 2026-11-17 (P2: reduced motion, Mood Log filter outline; P3: untyped buttons, table header scopes, login autofocus warning).

## Scope (what is and isn't in this PR)

In: reduced motion; Mood Log filter focus; `type` on buttons; Mood Log table header scopes and caption; login autofocus warning; tidy one malformed rule in Analytics.
Out (separate plans): touch-target sizes across pages and small text (needs a phone), page-title `h1` structure (belongs with `typeset`), dark mode (your decision), error/empty/loading states and double-submit guards (a bigger review, I'll propose after this).

## Global Constraints

- No visual change for people without `prefers-reduced-motion`. Under it: no sliding, spinning or shimmering, but state changes stay visible (colour and opacity changes keep working; a short colour fade is not motion).
- Focus must always be visible; use the global focus ring, never `outline: none` without a replacement of at least 3:1.
- No new dependency; no `.github/` changes.
- Version 4.21.11 with a plain-English changelog entry.

## Review Focus

- Spinner and skeleton screens under reduced motion must still say something is loading (text/static shape), not just stop silently.
- A `button` that is inside a `<form>` must keep submitting: only the login button is in a form and it already has `type="submit"`; all other buttons get `type="button"`.
- The Analytics `.mood-btn` rule (media query nested inside the rule, then another declaration) must still apply `font-size: 0.9rem` after tidying.
- The Mood Log filter input, when focused, shows the global ring on top of its border colour change.
- Login: focus still lands in the password field on load after removing `autofocus`.
